# Opt-in SSH smoke recipe

This is not authorization. Obtain a current request naming the host, disposable remote directory and permitted new surfaces. Use local Pi in an ordinary local cmux workspace. Existing prompts/resources are not fixtures.

Record versions/code snapshot, local/remote hostname/cwd, Pi PID/session filename, sentinels, exact created UUIDs and results.

1. Verify authentication/host trust outside chat; never collect secrets or create keys. Confirm the remote directory exists; creating it needs separate permission.
2. Create a unique authorized local sentinel without overwriting anything; record its hash.
3. Submit `Connect to <host> in <absolute path>` as an idle direct prompt. Check exact target, no redundant gate or config write, and visible state.
4. In that remote directory, test hostname/cwd and unique write/read/edit files, including special characters if authorized. Verify remote bytes and unchanged local sentinel independently.
5. Request new background remote/local helper tabs/splits. Preserve returned UUIDs and check hostname/cwd/PATH; creation alone proves no command success.
6. Request a same-project child. Verify local Pi/storage, configured-only target and no startup connection. Explicitly validate before remote work. Navigation/messaging checks are limited to authorized test sessions.
7. Only with separate permission, test persisted resume/failures/cancellation on named fixtures. Verify unsupported cwd/worktree/handoff/zoxide/layout/browser requests refuse without local preparation or draft changes. Never probe alternate hosts or kill unowned work.
8. Alias saving needs its own request and exact real-UI preview. Decline first; verify no write and independent one-off connection. Do not use production config as a general fixture.
9. Ask before closing exact owned surfaces/removing owned files. Never target by focus/title/first match. Explicitly clear SSH before local core operations.

On ambiguous/lost/timed-out creation, stop creating and inspect known IDs; never retry to discover the outcome. Cancellation does not prove remote termination or rollback. Do not reload Pi, type into existing prompts, copy credentials or clean up automatically.

Only the subsets in [historical evidence](ssh-native-validation.md) and [post-fix evidence](ssh-postfix-validation.md) have run. Other layouts and latest launch-size changes remain unverified; remote-owned placement remains unsupported.

# SSH-target Pi launches

Pi/cwd/session storage stay local. A ready target can transfer configured-only selection to a same-project fresh/related/reviewer tab/split, or a compatible explicitly named local resumed session. This is not remote Pi or a remote-worktree feature.

## Launch checks

`capturePiLaunch` holds a target ticket across preparation/dispatch. SSH launches skip local Git title discovery and refuse associated/remote-owned/unknown placement, new sidebar workspaces and handoffs.

The start tool permits omitted cwd only under SSH intent—even an explicit spelling of the local cwd is refused before stat. Worktree/continuation/zoxide guards precede local repository/path preparation. Non-ready intent cannot fall back locally.

Bundled local Pi launches preflight workspace locality before title inspection. Tabs/splits use protected single-RPC local creation; local sidebar workspaces retain create + respawn. Local PATH behavior is [documented separately](usage.md#pi-launch-path). Creation uncertainty never permits automatic retry.

## One-shot selection

`PI_CMUX_SSH_LAUNCH` contains version, nonce, issuance time, parent session ID, exact local cwd, target and optional exact local resume filename. No readiness, association, secrets or arbitrary environment crosses this channel. Ordinary launches strip inherited bootstrap; SSH launches replace it explicitly.

The consumer removes it before parsing. It checks strict fields, 60-second TTL, bounded process-local nonce replay protection, distinct parent/child IDs, exact cwd/resume filename and compatible saved/runtime state. Fresh branches may contain only neutral model/thinking startup metadata. Conflicting/clear/foreign/invalid state blocks fallback.

Success persists selection to the child's shared runtime as configured, never connects or validates. Central startup consumes it once before orientation adds entries. The environment is trusted local input, not cryptographic authentication; cross-process replay is not globally prevented and never grants readiness.

## Browsers and evidence

New browser opening under SSH intent is refused before binding/annotations. Target changes cancel in-flight local opens; existing annotation retry/stop, drafts and Pi confirmation remain intact.

Fixtures cover transfer/resume, malformed/replayed input, guards and races. Historical [native evidence](ssh-native-validation.md) verifies local Pi configured-only tab startup, not persisted child resume/remote execution or later launch-size changes. Other layouts, remote browsers/worktrees and automatic readiness remain unsupported.
